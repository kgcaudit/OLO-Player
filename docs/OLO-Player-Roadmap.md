# OLO Player — 전체 구상안 · 현황 · 로드맵

> 최초 구상부터 현재 구현 상태와 향후 계획까지 한 곳에 정리한 문서.
> "무엇이 아니라 왜"를 남기기 위한 프로젝트 기준 문서.

## 1. 전체 구상안 (최초 목표)

OLO Explorer의 검증된 재생 코어를 이식해, 별도 앱 **OLO Player**(`org.olo.player`)로
독립. nPlayer를 벤치마크한 4탭 골격 위에, OLO 디자인 시스템(밝은 테마·작은 제목·
선 아이콘·Cp 부품·의미 타일색)을 입힌 미디어 플레이어.

- **재생 코어**: 백그라운드 재생 + 알림, 자막(내장·외부·SAMI), 비디오/뮤직 분기.
- **네트워크 스트리밍**: HTTP(S) + FTP → 확장(SFTP·SMB·WebDAV·NFS), 서버 브라우저.
- **GUI 골격**: 하단 4탭(로컬·네트워크·재생목록·설정) + 설정 트리 + 공통 플레이어.
- **재생 기능(nPlayer 벤치마크)**: 터치 잠금·A-B 반복·반복 모드·배속·제스처(밝기/
  볼륨/탐색/배속/더블탭)·자막 스타일·슬립 타이머.
- **디자인**: OLO 토큰(라이트/다크), 실행 아이콘(재생 삼각형 + 찢는 모티프).
- **디자인 일관성**: 앱 전역이 하나의 시스템으로 읽혀야 함(행·타일·라벨·입력이 동일 리듬).

| 영역 | 상태 |

| 설정 트리 8종 전부 실동작(일반·목록·재생·비디오·오디오·자막·제스처·네트워크) | ✅ |

## 3. 미실현 / 이슈 (품질·완성도)

### 3-1. 디자인 일체화 (전역) — **최우선**
- **입력란 비대·이질**: 네트워크 4폼 + URL 다이얼로그가 Material `OutlinedTextField`
  (큰 박스, 떠 있는 라벨)를 사용 → 앱의 나머지(설정/목록 행)와 리듬이 다르고 공간 과다.
  → **컴팩트 OLO 입력 행**(라벨 좌 · 값/placeholder 우 · 48dp · 얇은 구분선)으로 통일.
- **자막 설정 화면 불일치**: 슬라이더·색상 스와치가 전폭으로 들어가 타 설정과 다르게 보임.
  → CpSettingRow 리듬에 맞춘 컴팩트 컨트롤로 통일.
- **공통 입력 컴포넌트 부재**: `CpField`(단일 입력 행)·`CpSelectRow`(선택)·`CpFieldSecret`
  (암호 가림+눈)·`CpDialog`(OLO 다이얼로그) 신설해 전역 재사용.

### 3-2. 네트워크 기능 미완/버그
- **서버 저장 없음**: 접속한 서버를 저장해 두고 원탭 재접속·편집·삭제하는 목록이 없음.
  (현재 `PlaylistStore.servers`는 host만 기록, 재구성 불가.)
  → 프로토콜별 서버 설정 영속(`SavedServer`) + 네트워크 랜딩에 **저장된 서버 목록**.
- **비밀번호 평문 노출(버그)**: 4개 폼 모두 `PasswordVisualTransformation` 미적용.
  → 가림 + 눈 아이콘 토글.
- **인코딩 수기입력 오류**: 자유 입력이라 오타·미지원 charset이면 접속 실패.
  → 프리셋 **선택(자동/UTF-8/EUC-KR/CP949…)** 로 교체.
- **오류 메시지 개선**: 접속 실패 원인(인증/타임아웃/경로)을 사람이 읽을 수 있게.

### 3-3. 완성도·성능
- **실제 썸네일**: 영상 목록이 타일+아이콘(프레임 없음). → Coil(+coil-video)로 프레임/커버.
- **릴리스 R8·용량 축소**: 디버그 23.5MB(smbj/BouncyCastle). → `isMinifyEnabled`+리소스
  shrink + material-icons-extended 정리로 릴리스 대폭 축소.
- **오디오·네트워크 설정 즉시 반영**: 현재 서비스가 플레이어를 1회 생성·재사용 →
  큐 로드 시 재적용하거나 설정 변경 시 재빌드.
- **태블릿/대화면**: 레일 시도했다 되돌림. 필요 시 마스터-디테일 2단 재설계.

### 3-4. 플레이어 고도화 (타 플레이어 벤치마크)
- 자막 지연/싱크(파일별), 스냅샷, PIP, 오디오 지연(A/V 싱크), 이퀄라이저, 화면비 상세.

## 4. 타 플레이어 디자인 조사 (요약)

| 플레이어 | 강점 | 취할 점 |
|---|---|---|
| **nPlayer** | 조밀한 목록, 라벨-값 다이얼로그(박스 없이), 서버 관리 | 컴팩트 폼 리듬·저장 서버 |
| **VLC** | 기능 밀도, 명확한 아이콘 | 절제된 컨트롤 |
| **MX Player** | 제스처·자막 편의 | 제스처 힌트 |
| **Infuse / Plex** | 포스터·커버 아트, 몰입 상세 | 썸네일/메타 카드 |
| **Kodi** | 소스 관리·스크레이핑 | 서버 저장·경로 관리 |

**결론**: OLO 디자인 방향(선 아이콘·조밀한 행·의미 타일)은 이미 좋은 축. 다만
**입력 폼만 Material 기본을 써서 이질적** — 이를 nPlayer식 컴팩트 라벨-값 행으로 통일하면
전역 일체감이 완성됨. 썸네일(Infuse/Plex식)과 저장 서버(Kodi식)는 완성도 축.

## 5. 향후 계획 (단계)

- **1단계 · 디자인 일체화 (최우선)**
  - `CpField`/`CpSelectRow`/`CpFieldSecret`/`CpDialog` 신설.
  - 네트워크 4폼 + URL 다이얼로그의 `OutlinedTextField` 전면 교체(컴팩트 행).
  - 자막 설정 화면 Cp 리듬으로 통일.
  - 암호 가림+눈, 인코딩 선택(프리셋).
- **2단계 · 네트워크 완성**
  - `SavedServer` 영속(프로토콜별) + 저장된 서버 목록(재접속/편집/삭제).
  - 오류 메시지 개선.
- **3단계 · 완성도**
  - 실제 썸네일(Coil), 릴리스 R8·용량 축소, 오디오/네트워크 설정 즉시 반영.
- **4단계 · 플레이어 고도화**
  - 자막 싱크(파일별)·스냅샷·PIP·오디오 지연·EQ.
- **5단계 · 출시 준비**
  - 서명(keystore)·버전·스토어 아이콘/스크린샷·수동 테스트 체크리스트.
